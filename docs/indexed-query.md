# 隔离式索引检索

普通 binlog、database、all 检索可通过 `RDS_BINLOG_INDEXED_QUERY_WORKER_URL` 切换为：既有搜索索引选候选 → 独立执行单元逐行组读取 Parquet → 稳定排序、去重、分页。它不维护第二套索引、不采集或重建历史正文；慢日志专用索引、audit 快路径、精确索引及聚合分析保留原路线。

## 查询行为

- 优先使用有效完整结果证书，否则先查既有搜索索引。v2 索引缺少的关键词字段不会被当作零命中；未知分区继续保守扫描。
- 正文使用必要列投影；每次只解码一个行组。OSS 使用固定 ETag 和 pack offset/length；每次 GET 都校验版本。无固定 ETag 时仅可使用校验 SHA-256 的本地正文，同一文件描述符完成校验和读取。
- 所有候选共用 256 MiB 读取预算、4096 次 GET、4096 个正文对象上限；重试及失败 GET 预留的字节不会退还。索引规划与读取均计入客户端 60 秒截止时间，独立原生进程另有最多 55 秒硬终止。
- 行组的 Parquet `total_byte_size` 上限为 64 MiB；这是解码前估算门，不是 RSS 保证。DuckDB 128 MB、spill 128 MB；结果保留完整字段，超过 16 MiB 报资源错误，不截字段、不把残缺页当成功。
- 跨行组/分区按事件身份去重；同一身份的已合并内容发生冲突时拒绝结果。时间戳相同时继续扫描，按原稳定排序键合并；分页采用去重后的全局次序。
- 结束前再次核对源内容修订与可见分区覆盖。变化则拒绝发布结果；只有完整结果才写现有结果证书。旧 LIKE 语义的探针和结果证书不再复用。
- 超时、取消、预算不足、身份错误及 worker 故障均不回退 CK 或主进程扫描。监督进程确认自身查询子进程退出后才返回终态；取消先于请求入场时也阻止该请求迟到启动。

## 执行单元

`compose.indexed-query.yaml` 是显式启用的叠加配置，未加入既有默认启动链。它与主应用使用同一镜像，仅只读挂载 `data/events`，不挂 metadata、索引、配置或凭据，不暴露宿主端口；OSS 使用本机 ECS RAM 角色。

配置将执行单元整个进程树限为 **1 GiB、无额外 swap、0.5 CPU、64 PID**，临时空间为 128 MiB scratch 加 16 MiB tmp。单查询串行执行，主应用任务并发设为 1。磁盘读/写分别限制为 8/4 MB/s；网络读取另由查询字节/请求总预算约束。

必须提供已有共享父 cgroup 的 `RDS_BINLOG_QUERY_CGROUP_PARENT` 和已核实设备的 `RDS_BINLOG_QUERY_IO_DEVICE`。配置缺失会阻止解析，不能自动落到无限额父组。不得为启用它修改父组额度、启动 CK、重建旧索引或停采集腾空间。

启用前核对云端镜像的提交 SHA，保留生产既有 compose/override 和容器额度；只在受控窗口操作主应用与 query-worker，不执行全栈重建。先核对实际父组、进程树额度、I/O 设备归属和剩余空间，再使用既有验收的生产延迟、积压、OOM 停止阈值。预算只是保护措施，拒绝、取消和超时都计失败，不计性能成功。

回退时移除主应用的 worker URL、恢复此前任务并发并使用原主应用配置；保留索引和缓存。原 CK 停止状态不因回退改变，因此不能把回退解释为恢复 CK 查询可用性。

## 验证范围

`tests/test_indexed_query_worker.py` 覆盖入口路由、跨来源分页、去重、未知索引、pack Range、跨对象预算、身份变化、源修订变化、缺失正文、原生子进程取消及迟到请求隔离。既有云端构建流程另在 1 GiB/0.5 CPU 容器中运行这些测试并核对实际 cgroup 参数。

这套契约回归不替代原完整 30 天固定 20 项、独立 oracle、持续归档及恢复验收，也不证明大查询 P95 提升。主应用的索引规划和结果合并开销、真实设备 I/O 归属与生产影响须在受控窗口实测；不要把尚未执行的云端步骤或部署配置当成运行证据。
